# e.basic 语言参考

e.basic 为 PROGRAM 程序增加扩展词条和设备内联汇编，沿用原生变量、数值表达式、优先级和控制流。

| 内存与 Flash | [PEEK / PEEK16](#peek--peek16)、[POKE / POKE16](#poke--poke16)、[COPY](#copy)、[FILL](#fill)、[FLASHWRITE](#flashwrite) |
| 矩阵与字符串 | [矩阵](#矩阵)、[字符串](#字符串) |
| 位运算 | [BAND、BOR、BXOR、SHL、SHR](#位运算) |
| 按键与计时 | [INKEY、TICKS](#inkey--ticks) |
| 机器码调用 | [CALL](#call调用机器码) |

直接内存访问可触及系统数据和 SFR（特殊功能寄存器）。地址宽度通过检查后，实际读写及副作用由硬件决定。程序须管理缓冲区或代码区的地址、用途、长度和有效期，避开当前栈、解析器及参数/结果缓冲；原生文件移动后重新取得地址。Flash 编程前须备份相关物理扇区并准备恢复方法。

设备菜单、输入与运行方法见 [e5800p 实现使用指南](BASIC_enhancements.md)。电脑端的 [PL/e](5800p-kits.md#ple) 用于开发固件。

## 语法、类型与求值

### 函数与语句

函数写成 `名称(参数,...)`，返回可继续参与原生表达式的数值；零参数函数也带括号，如 `INKEY()`。语句写成 `名称 参数,...`，完成操作后继续下一条 BASIC；`CLS`、`REFRESH` 是零参数语句。

普通语句沿用原生 BASIC 的换行或冒号分隔。`ASM`、`ENDASM` 各占独立行，块内按汇编文本解析。扩展词条由原生编辑器插入为 token，汇编正文存为 ASCII；PC 纯文本中的词条拼写对应设备源码中的 token 字节。

签名中的参数名可替换为表达式，例如 `POKE A,V` 可写成 `POKE B+1,65`。方括号标记可选参数，输入时填写所需的实参及分隔符。

#### 参数求值顺序

参数从左到右各求值一次，逐个检查类型；失败时停止后续求值。全部参数和命令区间检查通过后，命令才写入、绘图或调用。已执行的实参副作用保留：例如 `POKE CALL(A),300` 会先调用 A 处机器码，再因 300 超出字节范围而拒绝外层写入。

表达式继续使用原生优先级。下面将 31 赋给 A：

```text
1+2*BAND(255,15)→A
```

嵌套函数和原生表达式共用受检查的栈；可用栈空间决定嵌套深度。

### 参数类型

| 记号 | 合法值 | 用途 |
|---|---|---|
| `u8` | 0～255 的整数 | 字节、模式等 |
| `u16` | 0～65535 的整数 | word、长度、CALL 参数及返回值 |
| `u20` | 0～1048575 的整数 | 完整代码地址、FLASHWRITE 目的地址 |
| `u24` | 0～16777215 的整数 | 完整数据地址 |
| `i16` | −32768～32767 的整数 | 图形坐标 |
| `real` | 原生精度的有限实数 | 矩阵元素、SNUM 的数值参数 |

这些记号规定输入检查，BASIC 变量仍使用原生数值类型。整数参数须为范围内的有限实整数，虚部为零；小数、非零虚部、特殊数值、溢出及无符号参数中的负数均报错。函数返回原生实数标量，虚部为零。

坐标先检查 `i16`，再应用画布规则：`PSET -1,0,1` 因在画布外而直接返回；`PSET 65535,0,1` 因超出类型范围而报错。ASM 基址、汇编操作数和 TEXT 字符串另按各自的字面语法解析。

### 共同错误规则

| 条件 | 处理 |
|---|---|
| 缺少或多余参数、错误分隔符、括号未闭合、非法文本 | 语法错误 |
| 类型、数值、模式、地址区间或命令坐标条件不符 | 原生参数错误 |
| 新增工作帧或必要快照所需栈空间不足 | 原生内存错误 |
| 实参求值失败，如除零 | 保留原生错误状态与流程 |
| NOR 位冲突、编程或读回失败 | 显示 `WRITE ERROR`，进入原生错误流程 |

ASM 编译诊断见 [ASM 错误与定位](#asm-错误与定位)。硬件访问或机器码仍可能破坏系统或使程序挂起，未必能进入错误页。

## 内存访问

### 地址、字节顺序和所有权

数据地址是完整 `u24` CPU 字节地址，按 `段号×65536+段内偏移` 解释，与固件文件偏移区分。一般数据访问接受整个 24 位空间，包括 SFR；实际映射、ROM 的只读性、未映射区读值和外设副作用由硬件决定。

连续区间 `[A,A+N)` 在访问前检查 24 位溢出，末字节不得超过 `0xFFFFFF`；跨 64 KiB 数据段时继续递增段号。普通写命令逐字节写入，NOR 使用专门的编程/擦除流程。硬件故障或覆盖正在使用的内存可能留下部分结果；程序须自行安排读回、同步和恢复。

PEEK16/POKE16 按小端执行两次独立字节访问，允许奇地址和跨段。SFR 的读取也可能清除状态，因此访问顺序、COPY 方向以及两次访问之间的硬件活动都可能影响结果。

### PEEK / PEEK16

| 签名 | 参数 | 返回值与边界 |
|---|---|---|
| `PEEK(A)` | A：`u24` | 读一个字节，返回 `u8` |
| `PEEK16(A)` | A：`u24` | 依次读 A、A+1，返回 `低字节+256×高字节`，类型为 `u16`；读取前检查两字节区间，A 最大为 `0xFFFFFE` |

### POKE / POKE16

| 签名 | 参数 | 效果与边界 |
|---|---|---|
| `POKE A,V` | A：`u24`；V：`u8` | 向 A 发出一次普通字节写入 |
| `POKE16 A,V` | A：`u24`；V：`u16` | 先检查两字节区间，再向 A 写低字节、A+1 写高字节；A 最大为 `0xFFFFFE`，两次写入彼此独立 |

### COPY

`COPY D,S,N`：D、S 为 `u24`，N 为 `u16`，将 `[S,S+N)` 搬到 `[D,D+N)`。

先检查完整源、目的区间。对稳定的普通内存，重叠语义等同于 memmove：D<S 时从低到高，否则从高到低逐字节读写。D=S 仍可能读写并触发外设副作用。源可能被外设或其他代码更新时，由调用者准备所需的快照或同步。

### FILL

`FILL D,N,V`：D 为 `u24`，N 为 `u16`，V 为 `u8`。检查完整目的区间后，按地址递增将 N 个字节写成 V。

COPY、FILL、FLASHWRITE 在 N=0 时检查全部参数的数值宽度，包括 FILL 的 V，随后返回；N>0 时才检查非空区间并访问地址、写入或编程。

### FLASHWRITE

`FLASHWRITE DST,SRC,LEN`：DST 为 `u20`，SRC 为 `u24`，LEN 为 `u16`。从源缓冲向 NOR Flash 原始编程。

- LEN>0 时，目的必须完全落在连续 NOR 区 `0x80000–0xFFFFF`。支持奇地址、非整页长度和跨连续 Flash 银行；S1 末尾元数据也按普通目的字节处理。
- 源区间检查 24 位溢出，实际可读性沿用数据访问规则。源在预检和编程全过程必须稳定：实现会重新读取源，变化的 SFR 或目的覆盖源的布局需要先取得独立快照。
- LEN=0 时 DST 可为任意 `u20` 值，按上述零长度规则返回。

编程按以下顺序进行：

1. 检查地址和长度，读取源、目的，预检每一位。满足 `旧值 AND 新值 = 新值` 才可编程，即允许 1→0 或保持原值。
2. 任一字节需要 0→1 时，整次命令在编程前失败，目的保持原状；整个区间已相同时直接成功返回。
3. 有可编程差异时，重新读取源，分块编程并读回核对。开始编程后的硬件错误或断电可能留下部分结果。

### 显式擦除与物理扇区

NOR 擦除将整个物理扇区恢复为 1，使后续编程可以写入原来需要 0→1 的内容。擦除须通过 ROM 服务或已有工具显式执行。物理扇区、64 KiB CPU 银行和 FLASHWRITE 的 LEN 字节区间范围不同。

擦除前须备份并确认整个物理扇区可供删除，范围包括待写字节周围的数据。包含当前固件、原生文件或程序库的扇区被擦除后，相应代码和数据会失效。本机擦除入口、参数 ABI 和扇区编号见 [Flash 原始编程与显式擦除](BASIC_enhancements.md#flash-原始编程与显式擦除)。

Hex／汇编页面的 SAVE 通过 S1/S2 journal 事务副本提交和恢复；BASIC FLASHWRITE、ASM 使用原始编程，CALL 直接调用目标代码，可能改变 journal 数据。交替使用时须保持恢复副本与当前 Flash 一致，防止陈旧副本覆盖新内容。

### 调用者拥有的缓冲区示例

先取得独占、至少 8 字节的可写普通内存，保证程序执行期间有效。用原生输入将其完整十进制地址读入 B。

```text
?→B
FILL B,8,0
POKE B,65
POKE16 B+1,4660
PEEK(B)→A
PEEK16(B+1)→C
COPY B+4,B,3
```

执行后 A=65、C=4660，B+1/B+2 为十六进制 `34 12`，B+4～B+6 为 `41 34 12`；写入均在这 8 字节内。

## 矩阵

矩阵使用 `u16` 编号，与字符串分别存储。行列数、索引使用 `u16`，行列索引从 1 开始。元素使用原生实数精度，每项占 20 字节，单个矩阵最多 3276 项；实际容量取决于程序存储和运算工作副本所需的空间。

| 签名 | 操作 |
|---|---|
| `MDIM id,rows,cols` | 创建或重置矩阵，元素清零；行列数均须大于零 |
| `MSET id,row,col,value` | 写入一个 `real` 元素 |
| `MGET(id,row,col)` | 返回一个元素 |
| `MROWS(id)`、`MCOLS(id)` | 返回行数、列数 |
| `MADD dst,a,b`、`MSUB dst,a,b` | 同型矩阵相加、相减 |
| `MMUL dst,a,b` | 矩阵乘法；a 的列数须等于 b 的行数 |
| `MTRANS dst,src` | 转置 |
| `RREF(id)` | 原地化简为行最简形，返回秩 |
| `MDET(id)` | 返回方阵行列式，保留输入矩阵 |
| `MINV dst,src` | 求方阵的逆；奇异矩阵报参数错误 |

目标编号可与输入相同。RREF、行列式和求逆采用按绝对值选主元的消元法。编号尚未创建、索引越界、形状不符时报参数错误；存储或调用栈不足时报内存错误。

## 字符串

字符串使用 `u16` 编号，长度和索引按字节计算，索引从 1 开始。字符串与矩阵共用原生程序存储；复制、截取和拼接还需要调用栈空间。

| 签名 | 操作 |
|---|---|
| `SSET id,"text"` | 用双引号内的字面量赋值 |
| `SLEN(id)` | 返回字节长度 |
| `SMID dst,src,start,count` | 截取最多 count 字节；超过末尾时截短，起点超过长度时得到空串 |
| `SCAT dst,a,b` | 连接 a、b |
| `SFIND(hay,needle)` | 返回第一次匹配的位置；未匹配返回 0，空 needle 返回 1 |
| `SVAL(id)` | 解析十进制数，接受正负号、小数、E/e 指数和两端空格 |
| `SNUM id,value` | 将 `real` 转成 15 位有效数字的科学计数文本；零写成 `"0"` |
| `SPRINT id` | 每页显示 4 行、每行 16 字符；按 EXE 翻页或继续程序 |
| `SCHAR dst,byte` | 创建只含一个 `u8` 字节的字符串 |
| `SCODE(id,index)` | 返回指定位置的字节值 |

SMID、SCAT 的目标可与输入相同。SSET 的双引号用于界定字面量；用 SCHAR、SCAT 拼接引号等字节。SPRINT 使用 ROM 字体显示，零字节显示为空格；SLEN、SMID、SCAT、SFIND、SCODE 保留零字节。

编号尚未创建、起点为零、SCODE 越界及 SVAL 文本格式不符时报参数错误。字符串结果过长或临时空间不足时报内存错误。

## 位运算

| 签名 | 参数 | 返回值 |
|---|---|---|
| `BAND(A,B)` | A、B：`u16` | 逐位 AND，`u16` |
| `BOR(A,B)` | A、B：`u16` | 逐位 OR，`u16` |
| `BXOR(A,B)` | A、B：`u16` | 逐位 XOR，`u16` |
| `SHL(A,N)` | A：`u16`；N：0～15 的整数 | 左移 N 位，截为 16 位，低位补零 |
| `SHR(A,N)` | A：`u16`；N：0～15 的整数 | 逻辑右移 N 位，高位补零 |

移位 N=0 返回 A，N=16 报参数错误。

| 表达式 | 值 |
|---|---|
| `BAND(65535,255)` | 255 |
| `BOR(256,1)` | 257 |
| `BXOR(65535,255)` | 65280 |
| `SHL(32768,1)` | 0 |
| `SHR(32768,15)` | 1 |

## INKEY / TICKS

### INKEY()

立即扫描物理键盘。无键返回 0；有键返回 `1+KO×16+KI`，KO、KI 为从零开始的矩阵位号。多键取最小 KO 列及该列最小 KI 位；SHIFT、ALPHA 也参与扫描。持续按住同一键可持续返回同一值；按键先后或单次触发须由程序记录状态变化。

扫描会短暂操作键盘扫描状态，并恢复调用前的相关状态。原生 Getkey 保留自身键码和输入机制；具体键值见 [按键与计时](BASIC_enhancements.md#按键与计时)。

### TICKS()

读取原始 8 位计数器，返回 0～255，255 后回到 0。时钟和中断配置保持原状。

两次读取的间隔已知小于 256 个计数时，可用 `BAND(后值-前值+256,255)` 求间隔。以下示例测量一次整数表达式及相关 BASIC 执行经过的计数：

```text
TICKS()→A
BAND(65535,255)→B
BAND(TICKS()-A+256,255)→D
```

D 的单位是计数，可能为 0。差值只保留模 256 的信息，完整周期数须另行记录。每计数对应的秒数取决于机器时钟；模拟时间、墙钟时间、频率及实机校准见 [按键与计时](BASIC_enhancements.md#按键与计时)。

## CALL：调用机器码

### 地址与参数

`CALL(A[,P0[,P1[,P2[,P3]]]])` 调用已有机器码，并返回 ER0 的 `u16` 值。

A 是 `u20` 偶数代码地址，数值范围 0～1048574，覆盖 CSR 0～F。奇地址或超出宽度时在调用前报错；实际取指能力由硬件决定。本机从 ROM/Flash 执行代码，RAM/SRAM 用于数据。

| 参数 | 输入类型 | 入口寄存器 |
|---|---|---|
| P0 | `u16` | ER0 |
| P1 | `u16` | ER2 |
| P2 | `u16` | ER4 |
| P3 | `u16` | ER6 |

参数从 P0 起连续填写，省略的末尾参数补 0；其它寄存器初值由目标代码按需建立。返回 42 需要整个 ER0 为 42，即 R0=42、R1=0，`MOV ER0,#42` 宏可设置完整 ER0。

### 正常返回与保留的副作用

CALL 保存并恢复 BASIC 所需的寄存器、返回地址、栈指针、PSW、EA、数学工作区、解析器状态和字体。正常返回时将 ER0 转为原生实数，供表达式继续计算；用户对其它内存、图形、外设或 Flash 的修改保留。

### 被调用代码的责任

目标须已部署、可取指且能返回。CALL 检查参数后直接调用目标；编译、部署、必要的擦除和 journal 恢复须在调用前完成。

- 保持 SP 平衡，恢复原执行级别，以原生 RT 返回；本内联汇编器将其写作 `RET` 或 `END`。
- 嵌套调用自行保存 LR，例如 `PUSH LR` 配合 `POP LR; RET`，或 `PUSH LR` 配合 `POP PC`。
- 为自用数据、嵌套调用和中断预留栈空间，写入须避开 CALL 和解析器正在使用的数据；CALL 只检查自身需要的栈空间。
- ROM 服务使用其真实入口和 ABI，调用前准备参数，并将所需结果适配成 `u16`。

死循环、坏栈或其他异常控制流可能使执行停留在机器码中，需要外部暂停、复位或恢复方案。

## 图形

### 画布与刷新

逻辑画布为 96×31，原点左上，X 向右、Y 向下，合法像素为 X=0～95、Y=0～30；正文之外的状态扫描行保留。

绘图命令修改主帧缓冲，`REFRESH` 才将内容送到 LCD。原生 Locate、普通输出及程序结束后的 Done 共用该缓冲，可能覆盖图形；需要持续显示时，应以原生控制流保持程序运行。

### CLS / REFRESH

| 签名 | 效果 |
|---|---|
| `CLS` | 零参数语句，清除 31 行正文像素并保留状态行；LCD 保持原画面直到刷新 |
| `REFRESH` | 零参数语句，将当前主帧缓冲内容原样送到 LCD |

### PSET / POINT

| 签名 | 参数 | 效果与边界 |
|---|---|---|
| `PSET X,Y,M` | X、Y：`i16`；M：0/1/2 | 0 清除、1 置位、2 反色；先检查全部参数（含 M），画布外直接返回 |
| `POINT(X,Y)` | X、Y：`i16` | 返回缓冲中的像素 0/1；画布外返回 0 |

POINT 包含尚未 REFRESH 的绘图结果。

### LINE / RECT

`LINE X1,Y1,X2,Y2,M` 和 `RECT X1,Y1,X2,Y2,M` 的四个坐标为 `i16`，两个端点均须在画布内；M 与 PSET 相同。端点超界时在绘制前报参数错误，需要裁剪时由程序先计算画布内端点。

LINE 绘制包含两端点的整数栅格线，支持横线、竖线、斜线和单点。RECT 绘制空心矩形，自动归一化角点顺序，每个角只处理一次（XOR 也只反色一次）；零宽或零高退化为一条线，两者均为零退化为一个点。

### BLIT

`BLIT X,Y,W,H,A,M` 将内存位图绘制到帧缓冲。

| 参数 | 条件 |
|---|---|
| X、Y | `i16`，起点须在画布内 |
| W、H | 整数，W=1～96，H=1～32 |
| A | `u24`，源位图首字节地址 |
| M | 0 覆盖、1 OR、2 XOR |

源按行连续存储，每行 `ceil(W/8)` 字节，最高位为最左像素，末字节超出 W 的位忽略。完整源长度为 `ceil(W/8)×H`，最多 384 字节，访问前检查 24 位溢出；实际可读性沿用数据访问规则。

右侧和下侧超出画布的像素会裁剪，源区间仍按整个位图计算。覆盖模式同时复制 0 和 1；OR/XOR 遇到源 0 时保留目的像素。

源与被绘制的主帧缓冲正文相交时，先在栈上取得源快照，按调用时的源值绘制；栈不足在绘制前报错。其它源直接读取，须由程序保持稳定，或预先准备快照、外部同步。

### TEXT

`TEXT X,Y,"ASCII",F` 以覆盖方式绘制字面文本，清除整个字符单元内的背景；右侧裁剪，绘制后恢复原字体状态。

X、Y 为 `i16`。文本须直接写在双引号中，可含 0～32 个 ASCII `0x20–0x5F` 字符，遇到下一个双引号结束。空字符串合法，仍检查字体和坐标。

| F | 字体 | 坐标条件 |
|---|---|---|
| 0 | 3×5 小字，单元宽 4 | X=0～95 且为 4 的倍数，Y=0～26 |
| 1 | 常规字体，单元宽 6、高 7 | X=0～95，Y=0～24 |

其它 F 值报参数错误。

### 图形示例

#### 画边框、文字和像素

```text
CLS
RECT 0,0,95,30,1
TEXT 4,8,"HELLO",0
PSET 48,20,1
POINT(48,20)→A
REFRESH
```

A=1，REFRESH 将边框、文字和像素送到 LCD；程序结束后的原生输出仍可能覆盖画面。

#### 从自有缓冲区绘制位图

先取得独占、至少 8 字节的可读写普通内存，运行时将完整十进制地址输入 B。下面的 8×8 位图每行一字节，包含边框和两条对角线：

```text
?→B
POKE B,255
POKE B+1,195
POKE B+2,165
POKE B+3,153
POKE B+4,153
POKE B+5,165
POKE B+6,195
```

位图以覆盖模式绘制到逻辑坐标 (4,4)。

## 内联 ASM / ENDASM

### 块的执行语义

语法格式如下，基址和正文应替换为实际内容：

```text
ASM 十进制完整基址
汇编正文
ENDASM
```

基址须为十进制字面量，是 Flash 银行 8～F 内的完整偶数地址。ASM、ENDASM 各占独立行，构成单层块；ENDASM 是与 ASM 配对的零参数结束标记。

原生控制流实际执行到 ASM 才编译和调用；分支跳过或循环扫描会按行首 ENDASM 整体跨过正文，正文中的 BASIC 词条按汇编文本处理。执行顺序为：

1. 解析标签和输出长度，检查完整输出，再与实际 Flash 比较。
2. 字节相同则直接调用；不同则按 [FLASHWRITE 的原始 NOR 规则](#flashwrite)编程，覆盖确认和必要的擦除应在运行前完成。
3. 编程成功后从基址调用，相当于四个参数为零的 CALL。返回 ER0 的 `u16` 值写入 Ans，继续 ENDASM 后的 BASIC，由后续语句安排显示。

每次执行都重新编译当前源码并比较 Flash 内容。固定地址覆盖只修改输出范围，范围外机器码和块外硬编码引用保持原值，程序须维持布局及引用一致性。空块、纯 DB/DW 块或缺少返回指令的块也会尝试调用基址；作者须安排可正常返回的执行路径。

### 源码与布局

助记符、寄存器和标签按 ASCII 大小写折叠识别，字符串字节保留原样。元素间支持单个或连续空格，也可留空行；引号外的 `;` 开始行注释。

标签写成 `NAME:`，可独占一行或放在指令/数据之前。名字长 1～8 字符，首字符为 A～Z 或 `_`，后续可用字母、数字、`_`；大小写折叠后须唯一。标签记录当前段内 PC，支持前向和后向引用。

| 资源或布局 | 规则 |
|---|---|
| 源码与标签容量 | 按实际文件、近地址和栈资源限制；资源允许时可超过 32 个标签、每行 64 字符 |
| 栈占用 | 固定工作帧 128 字节，每个标签再占 12 字节，另需调用、中断及编程/调用包装空间 |
| 输出范围 | 全部输出留在同一 64 KiB 代码段，长度最多 65535 字节 |
| 对齐 | 每条指令起点须偶数；数据地址及输出总长度可为奇数，DB 后需要时显式添加对齐字节 |
| 结尾 | 按源码逐项输出，可用数据或其它指令结束；RET/END/POP PC 等返回路径由作者写出 |

### 数值、寄存器和地址表达式

数值可为十进制或 `0X` 十六进制，`#` 可选，支持一元正负号；负值仅对相应有符号操作数合法。地址表达式可以是标签、`标签+整数` 或 `标签-整数`，结果须符合操作数宽度。

| 操作数 | 范围 |
|---|---|
| Rn | R0～R15 |
| ERn | ER0/2/4/6/8/10/12/14 |
| XRn、QRn | XR0/4/8/12；QR0/8 |
| `u8`、`u16` 立即数 | 0～255；0～65535 |
| 位号、移位立即数 | 0～7 |
| `i7` | 十进制 −64～63，或十六进制原始位型 `0X00–0X7F` |
| `i8` | 十进制 −128～127，或原始位型 `0X00–0XFF` |
| `i16` 位移 | 十进制 −32768～32767，或原始位型 `0X0000–0XFFFF` |

普通分支、JMP、CALL 的目标可为段内 `u16` 地址、标签/标签偏移，或与当前块同银行的完整地址；目标须为同代码段偶数地址。CALL_SYS 接受完整 20 位偶数字面地址，CSR 数值可为 0～F。

相对分支的 word 位移为 `(目标−(PC+2))/2`，范围 −128～127。目标可在块外，也可使用数据标签及标签偏移。编译器检查地址与位移；作者须核对目标是否位于完整指令开头及执行路径是否正确。

### 当前支持的指令形式

以下为设备内联编译器支持的指令形式。R、ER、XR、QR 替换为具体寄存器，各位置可独立选择；`target` 遵守上述目标规则。PC 汇编器与 CPU ISA 的支持范围见各自文档。

#### 算术与逻辑

| 类别 | 形式 |
|---|---|
| 加法 | `ADD R,#u8`、`ADD R,R`、`ADDC R,#u8`、`ADDC R,R`、`ADD ER,#i7`、`ADD ER,ER` |
| 减法 | `SUB R,R`、`SUBC R,R`、`SUB R,#u8`（宏） |
| 逻辑 | `AND R,#u8`、`AND R,R`、`OR R,#u8`、`OR R,R`、`XOR R,#u8`、`XOR R,R` |
| 移位 | `SLL R,#bit`、`SLL R,R`、`SLLC R,#bit`、`SLLC R,R`、`SRL R,#bit`、`SRL R,R`、`SRLC R,R`、`SRA R,#bit`、`SRA R,R` |
| 乘除 | `MUL ER,R`、`DIV ER,R` |

#### 比较、移动与控制流

| 类别 | 形式 |
|---|---|
| 比较 | `CMP R,#u8`、`CMP R,R`、`CMPC R,#u8`、`CMPC R,R`、`CMP ER,ER` |
| 单寄存器运算 | `DAA R`、`DAS R`、`NEG R`、`EXTBW ER` |
| 移动 | `MOV R,#u8`、`MOV R,R`、`MOV ER,ER`、`MOV ER,SP`、`MOV SP,ER`、`MOV ER,#u16`（宏） |
| 相对分支 | `BGE target`、`BLT target`、`BGT target`、`BLE target`、`BGES target`、`BLTS target`、`BGTS target`、`BLES target`、`BNE target`、`BEQ target`、`BNV target`、`BOV target`、`BPS target`、`BNS target` |
| 跳转/调用 | `JMP target`、`CALL target`、`CALL_SYS u20` |

#### 访存、栈与其它指令

| 类别 | 形式 |
|---|---|
| 字节访存 | `L R,addr`、`L R,[ER]`、`L R,disp[ER]`；相应的三个 `ST R,...` 形式 |
| word 访存 | `L ER,addr`、`L ER,[ER]`、`L ER,disp[ER]`；相应的三个 `ST ER,...` 形式 |
| 通用寄存器栈 | `PUSH R`、`POP R`、`PUSH ER`、`POP ER`、`PUSH XR`、`POP XR`、`PUSH QR`、`POP QR` |
| 控制寄存器栈 | `PUSH LR`、`POP LR`、`PUSH EA`、`POP EA`、`POP PC` |
| 其它 | `TB R.bit`、`ADD SP,#i8`、`SC`、`RC`、`CPLC`、`NOP`、`RET`、`END` |

#### CPU 效果与宏约定

指令直接采用 nX-U8 的寄存器、标志和机器语义，算术溢出、除零、SP 修改及访存结果由 CPU 决定，需要的检查应在机器码中编写。

BGE/BLT/BGT/BLE 用于无符号比较，带 S 的对应形式用于有符号比较；BEQ/BNE 测零标志，BNV/BOV 测溢出，BPS/BNS 测符号。SC/RC/CPLC 设置/清除/翻转进位，TB 测试指定位。

- `SUB Rn,#u8` 为 8 字节宏：保存临时字节寄存器、装入立即数、执行寄存器 SUB、恢复临时寄存器。Rn=R0 时临时寄存器为 R1，否则为 R0；保留临时寄存器和 SUB 结果标志，需要额外栈访问。
- `MOV ERn,#u16` 为 4 字节宏，先 MOV 低字节寄存器，再 MOV 高字节寄存器；长度及标志效果按这两条指令计算。
- `END` 是 `RET` 的别名，生成原生 RT 机器码；汇编文本块仍以 ENDASM 结束。
- 目录外形式，如 `SRLC R,#bit`、独立 DSR、寄存器间接 CALL/JMP，可在核实真实机器码后用 DB/DW 编码。

### L/ST 数据段前缀

`addr` 是段内 `u16` 绝对地址，`disp` 是 `i16` 位移。L/ST 地址操作数可加立即段号 0～F 和冒号。以下展示语法，地址与寄存器值须按实际程序准备：

```text
L R0,4:[ER2]
ST ER0,4:0x0100
L R1,4:-2[ER6]
```

显式前缀增加 2 字节，与后面的内存指令构成一条完整指令；标签只能放在完整指令边界。省略前缀时采用原生无前缀默认数据段语义，需要指定段时就在该条 L/ST 上填写。BASIC 的完整地址和前一条指令的前缀各作用于对应访问。

设备文本语法支持上述立即段形式；寄存器 DSR、复用前缀等其它机器码形式按目录外指令用 DB/DW 编码。

### DB / DW

DB 发出一个或多个 `u8` 数值或 ASCII `0x20–0x7E` 字符串，可混合；字符串内双引号写成两个双引号。DW 发出一个或多个 `u16` 数值，采用小端。数值位置也可使用符合宽度的标签或标签偏移。

数据声明示例：

```text
DB 1,0xFF,"ABC","A""B"
DW 4660,0xABCD
```

其中 `"A""B"` 发出 `41 22 42`，DW 发出 `34 12 CD AB`。数据按列表原样输出，终止 NUL、对齐字节及跳过数据的控制流须显式写出；数据位于执行路径中时，CPU 会把它当指令。

### 返回 42 的示例

本例使用完整 CPU 地址 598016（9:2000）。运行前须确认该处至少 16 字节为独占、可执行的 Flash，核对原生库布局和 NOR 位是否允许写入；需要擦除时先备份并确认整个物理扇区可删除。栈空间和活动数据隔离按 CALL 的要求准备。

```text
ASM 598016
PUSH LR
MOV ER0,#40
CALL add_two
POP PC
add_two:
ADD ER0,#2
RET
ENDASM
Ans→A
CALL(598016)→B
```

正常执行后 A=42、B=42。BASIC CALL 负责保存和恢复寄存器等状态；块内汇编 CALL 直接调用机器码。本例用 PUSH LR / POP PC 保存嵌套调用的返回地址。

### ASM 错误与定位

编译错误在编程前显示 `ASM ERROR` 及原因，并通过原生错误/编辑流程定位源码；返回编辑器的按键见实现指南。

| 原因 | 触发条件 |
|---|---|
| `BAD OPERAND` | 未支持的助记符/形式、非法寄存器、数值或字符、错误目标、嵌套 ASM 等语法问题 |
| `DUP LABEL` | 大小写折叠后的标签重复 |
| `NO LABEL` | 未定义标签 |
| `BR RANGE` | 相对分支超出 −128～127 word |
| `ADDRESS RANGE` | 基址、指令起点、输出或近代码段地址越界，或不满足对齐 |
| `NO ENDASM` | 有效源码范围内缺少结束标记 |

原因取决于检测阶段，例如目标在操作数匹配时被拒绝可显示 BAD OPERAND。源码和标签按实际文件、近地址及栈资源检查；栈不足走内存错误，NOR 位冲突或编程/核对失败走 WRITE ERROR。跳转目标和返回路径须另行核对。
