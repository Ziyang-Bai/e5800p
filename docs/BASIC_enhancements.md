# e.basic：e5800p 实现使用指南

本文介绍如何在 fx-5800P 的原生 PROGRAM 中输入、保存和运行 e.basic 程序。开始前，在完整型号副本中[加载 e5800p 并备份](e5800p.md#加载与备份)。固件加入 25 个 NX 词条，沿用原生变量、表达式、控制流和文件保存；TABLE/GRAPH、ASM/Hex、系统 MEMORY、关机签名及 Built-in Prog/YAMAYO 库继续保留。

- [输入与运行](#输入与运行)：新建程序、NX 菜单和键盘操作。
- [BASIC 图形](#basic-图形)：画边框、文字和像素。
- [内联 ASM](#内联-asm)：编译并调用返回 42 的程序。
- [内存与底层函数](#内存与底层函数)、[CALL](#call返回-basic-的汇编调用)：本机地址、ROM 服务和使用风险。

完整语法、参数宽度和错误规则集中在 [e.basic 语言参考](e.basic.md)。本文保留本机的菜单、键位、内存映射与 ROM 约定。

## 输入与运行

在 **MODE → 5:PROG → 1:PROG** 选择 **NEW**，输入一个未使用的程序名（例如 `CLOCK`），按 EXE，再选择 **COMP** 类型进入编辑器。输入下面这个只有一行的程序：

```text
TICKS()
```

1. 按 **FUNCTION → 右 → 1:NX → 4:TOOLS**，再按右键翻到第二页，选 **3:TICKS**。编辑器会插入 `TICKS(`，补上右括号。
2. 按 EXE 结束这一行，再按 EXIT 返回程序菜单；必要时再按一次 EXIT。源码由原生 PROGRAM 保存。
3. 选择 **RUN**，选中 `CLOCK` 后按 EXE 运行。表达式返回 0～255 的原始计数值，重复运行时数值随模拟时间变化。
4. 用 **EDIT** 重开 `CLOCK`，可以继续修改同一份源码。

模拟器中的文件保存与落盘是两个步骤：保留到下次启动时，按[原生 OFF → 关闭窗口 → 重开](e5800p.md#原生-program-的模拟器持久化)操作。

### NX 菜单

普通 BASIC 区按 **FUNCTION → 右 → 1:NX** 打开扩展类别。菜单每页四项，数字 1～4 选当前页的条目，左/右翻页，EXIT 返回上级。

| 类别 | 词条顺序 |
|---|---|
| `1:MEM` | PEEK、PEEK16、POKE、POKE16、COPY、FILL、FLASHWRITE |
| `2:ASM` | CALL、ASM、ENDASM |
| `3:GFX` | CLS、PSET、POINT、LINE、RECT、BLIT、TEXT、REFRESH |
| `4:TOOLS` | BAND、BOR、BXOR、SHL、SHR、INKEY、TICKS |

函数插入词条和左括号，语句插入词条和空格。用原生编辑器补齐数字、变量、逗号和括号；每个双字节 token 是一个完整的移动和删除单位。原生 Getkey、Locate、While 等仍从原菜单输入。表达式的求值顺序、嵌套及类型检查见[语法、类型与求值](e.basic.md#语法类型与求值)。

### 键盘输入

普通 BASIC 按原生键盘规则输入；ASM 正文改为 ASCII 文本输入。两者都用方向键移动光标、删除键修改、EXE 换行。ASM 与 ENDASM 各占独立行。

进入 ASM 正文后，ALPHA 输入字母，数字键输入 ASCII 数字，FUNCTION 打开以下菜单；分页和选择键与 NX 菜单相同：

| 菜单 | 内容 |
|---|---|
| `1:OP` | 六类共享指令目录，插入可编辑的操作数模板 |
| `2:REG` | R0～R15、ER0/2/…/14、XR0/4/8/12、QR0/8、SP、LR、EA |
| `3:SYM` | 空格、逗号、冒号、方括号、#、下划线、双引号、分号及算术符号 |
| `4:BLOCK` | DB、DW、ENDASM |

将模板中的 `LABEL` 改为实际标签，按程序需要修改 `R0`、`#0` 等默认操作数。ENDASM 只能在行首插入，之后的新行恢复普通 BASIC 输入。编辑器按源码中的块边界判定输入模式，修改 ASM/ENDASM 后会重新判定。

## BASIC 图形

新建一个 COMP 程序，通过 **FUNCTION → 右 → 1:NX → 3:GFX** 插入绘图词条，输入以下完整程序。While/WhileEnd 从原生控制流菜单插入。

```text
CLS
RECT 0,0,95,30,1
TEXT 4,8,"HELLO",0
PSET 48,20,1
REFRESH
While 1
WhileEnd
```

这里的 `RECT` 覆盖整个 96×31 逻辑画布，模式 `1` 表示置位；`TEXT` 的末参数 `0` 选择 3×5 小字，X=4 满足四像素对齐；`PSET` 在 `(48,20)` 置一个像素。保存并运行后，边框、文字和点停留在屏幕上，按 **AC** 中止。

本机将逻辑 Y 映射到物理 Y+1，保留最上面的状态扫描行。绘图先修改主帧缓冲，**REFRESH 才刷新 LCD**。原生 Locate、普通输出和程序结束时的 Done 共用显示缓冲，可能覆盖图形顶部正文；示例中的循环用于保持画面，AC 中止后由原生界面接管。

图元模式、裁剪、BLIT 源布局及 TEXT 字符范围见[图形参考](e.basic.md#图形)。本机的常规字体为 ROM `07`，小字入口见[共享入口迁移](#共享入口迁移)。

## 内联 ASM

### 返回 42 的完整程序

本例把机器码放在 **9:2000（0x92000，十进制 598016）**，与 [`examples/return42.asm`](../examples/return42.asm) 使用同一段汇编源码。银行 9 属于原生 Built-in Prog/YAMAYO 库；先备份型号并确认目标范围可供覆盖。目标字节须允许 1→0 编程；需要 0→1 时先擦除整个 sector 4，这会删除银行 9 中的原生库数据。扇区与操作见 [Flash 原始编程与显式擦除](#flash-原始编程与显式擦除)。

在新建的 COMP 程序中，从 **FUNCTION → 右 → 1:NX → 2:ASM** 插入 ASM，补上十进制基址 `598016`。用[键盘输入](#键盘输入)中的 OP、REG、SYM 菜单输入正文，再从 BLOCK 插入 ENDASM；最后两行回到普通 BASIC 输入。

```text
ASM 598016
PUSH LR
MOV ER0,#40
CALL add_two
POP PC
add_two:
ADD ER0,#2
RET
ENDASM
Ans→A
CALL(598016)→B
```

`PUSH LR` 保存返回 BASIC 的地址，内部 `CALL add_two` 将 ER0 从 40 加到 42，`POP PC` 返回 BASIC。ASM 的结果写入 Ans，下一行将它存入 A；最后一行再次调用同一地址，把结果存入 B。按前述流程保存并运行后，在原生变量查看或计算中读取 A、B，两者应均为 42。

执行到 ASM 块时，固件直接编译、预检、编程并调用，目标范围应在运行前确认。相同机器码再次运行时直接调用；执行等价于四个零参数的 CALL。改动程序可能产生 0→1 位转换，届时预检会拒绝写入，需要重新安排擦除和恢复。PC 上编译、部署和调试同一源码的命令见 [Python 工具链](5800p-kits.md#python-工具链)。

### 语法与限额

ASM 正文按原始文本保存。If/Else、For/While、Break、Goto 的扫描将正文作为整体跨过；只有控制流实际执行到块时才编译并调用。完整契约见[内联 ASM / ENDASM](e.basic.md#内联-asm--endasm)，其中包括[源码与布局](e.basic.md#源码与布局)、[数值、寄存器和地址表达式](e.basic.md#数值寄存器和地址表达式)及[支持的指令形式](e.basic.md#当前支持的指令形式)。

本机编译器使用原生调用栈：固定工作帧 128 字节，每个标签另占 12 字节，并为调用、中断和写入包装留出余量。可用标签数取决于实际剩余栈；源码容量和行长还受原生文件及近地址范围限制。栈耗尽按原生内存错误退出。

编译错误显示 `ASM ERROR` 和原因，按 EXIT 回到原生错误/编辑流程并定位源码行。各原因及写入错误的区别见 [ASM 错误与定位](e.basic.md#asm-错误与定位)。

### 共享入口迁移

ASM 菜单、反汇编与文本编译器共用指令记录和编码器。小字公共入口为 **F:9000**，指针表为 **F:9400**，补充字模为 **F:9480**，寄存器接口保持原样，见 [ROM 小字体调用指南](ROM_small_font.md)。硬编码旧段 9 扩展入口的用户汇编须按新地址重新汇编；段 9 仍归原生程序库使用。

## 内存与底层函数

BASIC 使用完整 CPU 地址，按 `段号×65536+段内偏移` 计算；文件工具使用 Flash 物理偏移，Hex 页用十六进制输入。例如 CPU `9:2000` 在 BASIC 中写作 `598016`，对应 Flash 文件偏移 `0x12000`。

一般数据访问接受完整 **24 位地址空间，包括 SFR**。数值和区间通过检查后，实际读写由硬件映射决定：ROM 只读，映射空洞和 SFR 按硬件行为响应，NOR 使用专门的编程流程。已知映射包括：

| 区域 | CPU 地址 |
|---|---|
| ROM0 / ROM1 | `0:0000–7FFF` / `1:0000–FFFF` |
| 片内 RAM | `0:8000–8DFF` |
| SRAM | `4:0000–7FFF` |
| Flash | `8:0000–F:FFFF` |

RAM/SRAM 由原生系统使用，直接写入可能破坏程序文件、变量、显示状态或活动栈。缓冲区须在使用期间有效，并与当前命令的栈、参数和返回缓冲分离；文件增长、复制、改名后重新取得地址。SFR 访问可能清状态、触发外设或改变中断，须按对应外设的约定使用。

PEEK/POKE、COPY/FILL 的宽度、重叠和零长度行为见[内存访问](e.basic.md#内存访问)，BAND/BOR/BXOR/SHL/SHR 见[位运算](e.basic.md#位运算)。

### Flash 原始编程与显式擦除

FLASHWRITE 和内联 ASM 对 `8:0000–F:FFFF` 执行原始 NOR 编程，包含落在目标范围内的 S1 元数据。只有 **1→0** 或保持原位值可直接编程；任一字节需要 **0→1** 时，整次操作在预检阶段失败。相同内容直接完成。源须在检查和编程期间保持稳定，SFR 等实时数据应先复制为稳定快照。完整参数与步骤见 [FLASHWRITE](e.basic.md#flashwrite)。

实际编程故障或断电可能留下部分结果。擦除前备份整个物理扇区，并安排恢复方式；擦除会影响待写区间周围的全部数据。S0 和 C～F 含正在运行的固件，擦除或覆盖可立即使系统失效。FF 表示当前字节处于擦除态，空间用途仍由原生系统和固件布局决定。

配套 ROM 的擦除入口是 **0:4EF4（十进制 20212）**，扇区编号由 ER0 的低字节 R0 传入。调用格式为 `CALL(20212,sector)`，其中 `sector` 须替换成已核对的物理扇区编号。CPU 用八个 64 KiB 银行 8～F 寻址，擦除服务则按 **11 个物理扇区** 编号；ROM `0:096A` 的地址表与 `0:4EF4` 服务对应如下（文件区间右端不含）：

| sector | Flash 文件物理区间 | CPU 区间 | 大小 |
|---|---|---|---|
| 0 | `[0x00000,0x04000)` | `8:0000–3FFF` | 16 KiB |
| 1 | `[0x04000,0x06000)` | `8:4000–5FFF` | 8 KiB |
| 2 | `[0x06000,0x08000)` | `8:6000–7FFF` | 8 KiB |
| 3 | `[0x08000,0x10000)` | `8:8000–FFFF` | 32 KiB |
| 4～10 | `[(sector−3)×0x10000,(sector−2)×0x10000)` | 银行 `sector+5` 的整个 `0000–FFFF` | 各 64 KiB |

`CALL(20212,4)` 的擦除范围是整个银行 9，包含示例 `9:2000` 周围的全部原生库数据。确认整扇区可供删除、备份和恢复方法均已准备后再调用。

旧 Hex／页面编程界面的 S1/S2 journal 继续使用原协议：S1 `8:4000–5FEF` 为数据，末 16 字节为元数据，S2 为备份。它只服务于旧界面的提交与恢复；BASIC FLASHWRITE、ASM 和 CALL 使用原始编程或直接调用路径。混用时须同步管理原始写入结果和旧界面恢复副本，避免旧副本覆盖新数据。

### 按键与计时

INKEY 按物理矩阵编码 `1+KO×16+KI`（KO/KI 从 0 起算），持续按住返回同一值；多键取最小 KO 列及该列最小 KI 位，SHIFT、ALPHA 也算物理键。本型号按住 `1` 返回 67，SHIFT 返回 7，全部松开返回 0。原生 Getkey 使用自己的菜单键码。

TICKS 读取原始八位计数器并保留现有时钟配置。当前模拟器模型标称 **128 Hz 的模拟时间计数**，相对宿主墙钟的速度受模拟器运行速度、暂停和调试影响。回绕计算及适用间隔见 [INKEY / TICKS](e.basic.md#inkey--ticks)；实机频率须单独校准。

## CALL：返回 BASIC 的汇编调用

本机从 **ROM0/1 和 Flash8～F** 取指，RAM/SRAM 用作数据空间。CALL 的地址数值允许完整 20 位偶数地址、CSR 0～F，但能否取指取决于实际映射；选择 ROM 服务时还须核对入口和 ABI。

参数经 ER0/ER2/ER4/ER6 传入，返回值取 ER0。完整的省略参数规则、现场保护和返回约定见 [CALL：调用机器码](e.basic.md#call调用机器码)。例如只给 R0 写字节结果时，还应清 R1；嵌套调用须保护 LR，[返回 42 的程序](#返回-42-的完整程序)展示了这种做法。

调用包装恢复 BASIC 所需的寄存器、返回现场、数学区、解析器现场和字体状态；用户代码的内存写入保留。目标代码须平衡 SP、恢复原执行级别并正常返回。坏栈、死循环或关闭中断可能使控制权停留在机器码中；作者负责检查返回路径，并在调用前安排备份和需要的 journal 恢复。

## 验证与使用边界

此前二进制的运行记录只对应各自镜像和测试范围。当前构建应记录同次 `python tools/casio_tool.py verify` 的输出及镜像 SHA-256，步骤见[模拟器验证](verification.md#模拟器验证)；完整镜像哈希会随保留的原生用户数据银行变化。

模拟器结果与实机结果分别记录。实机 NOR 时序、断电行为和 TICKS 频率仍需独立硬件实验验证。公开仓库提供 Python 固件源码；原始 ROM、Flash、完整型号和生成的完整固件留在用户本地。
